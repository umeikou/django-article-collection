# 小宇宙播客收藏功能需求

## Summary

在现有 Django 5.2、Django REST Framework、SQLite、Gunicorn 和 systemd 的文章收藏系统中增加小宇宙单集播客收藏。小宇宙链接不能沿用当前同步收藏流程：提交后必须快速持久化任务并返回，后续元数据解析、免费内容判定、转写、全文 AI 分析和文章生成由独立的数据库驱动 worker 完成。完成后，播客以平台为 `xiaoyuzhou` 的普通 `Article` 出现，全文文字稿存入 `Article.content`，并继续参与既有的搜索、列表、统计和管理功能。

已检查当前实现：`ArticleCollectionService.collect_article` 会在 Web/API 请求中同步解析和 AI 分析；`CollectionTask` 只有粗粒度状态；`DeepSeekAIService.analyze_article` 会截断至前 3,000 个字符；现有 API 路由为 `/api/articles/` 和 `/api/tasks/`。仓库有大量与本功能无关的未提交修改和未跟踪文件，实施不得覆盖、清理或重构这些变更。

### Assumptions

- 支持的目标是小宇宙**单集** URL，即主机为 `xiaoyuzhoufm.com` 或其 `www` 子域且路径为 `/episode/<episode-id>`。节目主页、短链、搜索页和非 HTTP(S) URL 不属于本期支持范围。
- “受限内容”包括元数据明确不是 `FREE` 的 `pay_type`，以及标记为私有媒体的单集。任何无法可靠获取或判定元数据、免费状态或可用音频 URL 的情况都不得提交 ASR。
- 对同一规范化单集 URL，同一时间只能存在一个会产生 ASR 请求的活跃任务。已完成的 Article 仍按既有“已存在”语义处理；已提交但外部结果不确定的任务不自动重新提交，而由用户明确重试或人工处理。
- “直接付费 ASR”表示对已验证为免费且可访问的单集，worker 无需额外用户确认即可提交 ASR。它不表示可绕过账户余额、服务端限流或平台访问限制，也不允许自动充值。

## Functional Requirements

### 1. 识别和异步提交

- 系统必须在既有单篇收藏入口 `POST /api/articles/collect/` 检测符合上述规则的小宇宙单集 URL。普通文章 URL 的请求、响应语义和同步收藏行为必须保持兼容。
- 对有效的小宇宙 URL，API 必须在数据库中创建并持久化播客关联记录和 `CollectionTask` 后立即返回 HTTP 202。响应必须包含任务 ID、任务状态查询 URL、初始状态、阶段和进度信息；请求处理不得下载音频、调用 ASR、等待转写或等待 AI 分析。
- Web 收藏页面和批量收藏页面必须能正确识别 API 的 202 播客响应，不将其显示为失败或已完成文章。单个提交完成后应显示可持续更新的播客处理卡片。
- URL 格式不合法或不属于支持的小宇宙单集的 URL 必须按当前输入验证或普通文章流程处理。已存在文章的行为不得因本功能改变。重复提交活跃播客任务不得创建第二个会计费的 ASR 任务，应返回或展示既有任务。

### 2. 元数据和访问限制

- 后台任务必须通过已安装技能的绝对路径调用小宇宙元数据脚本，以取得单集标识、标题、节目名、作者、发布时间、说明、时长、免费状态、私有状态、音频 URL 和候选热词等可获得元数据。实现必须以实际已安装脚本支持的 CLI 和 JSON 输出为准。
- 元数据获取成功后，任务必须将可安全保存的播客元数据持久化到 `PodcastEpisode`，并记录当前阶段和用户可理解的事件消息。原始或签名音频 URL 不得出现在对外 API、前端事件、异常文本或日志中。
- 只有 `pay_type == FREE` 且未标记为私有或受限的单集可进入 ASR 阶段。付费、会员、私有或其他受限内容必须终止为不可重试的拒绝结果，提供“该单集为付费或受限内容，未提交转写”的可执行说明，并保证没有 ASR 提交。
- 音频 URL 缺失、元数据结构变化、平台访问失败或音频不可用必须生成可操作的失败说明和任务事件。可安全重试的临时失败可按任务重试策略处理；不安全或确定性失败不得无限重试。

### 3. 持久化任务状态、worker 和恢复

- 新增或扩展数据模型必须覆盖：`PodcastEpisode`；与播客结果关联所需的 `Article` 和 `CollectionTask` 字段；以及按时间追加、可查询的任务事件历史。持久化状态须足以在 worker 停止、进程崩溃或服务器重启后恢复而不丢失任务进度。
- 任务必须提供明确阶段，至少能区分：排队、元数据检查、免费/受限判定、等待或提交 ASR、轮询 ASR、获取/生成文字稿、分块 AI 分析、最终汇总、成功、失败、拒绝和取消。每个非终态阶段必须暴露总体进度和当前工作说明；分块分析还必须暴露已完成块数与总块数。
- 实现必须提供独立于 Gunicorn 的 Django management-command worker，并提供 systemd unit 与运维文档，说明如何安装、配置、启动、停止和查看 worker。该工作不部署、启用、重启或修改任何实际 systemd 服务。
- 在 SQLite 单 worker 部署前提下，worker 必须以持久化租约和心跳安全领取任务，避免一个任务被并发处理。过期租约必须可恢复；取消、终态和租约归属必须在持久化状态层受到保护。网络调用和长轮询不得持有长时间数据库事务或阻塞 Web 请求。
- Worker 必须支持安全的瞬时失败重试和退避。网络超时、暂时性平台/ASR 服务异常、429 限流和 worker 中断可恢复；API key 缺失或无效、余额不足、付费/私有内容、不可解析元数据、不可用音频、无效外部结果和 ASR 明确失败应提供分类明确的终态或需人工干预状态。所有失败必须有面向用户的安全说明和内部任务事件；不得泄露密钥、授权头、签名 URL 或完整外部响应。

### 4. ASR 集成、计费保护和音频生命周期

- 必须用 Python 子进程和绝对脚本路径集成已安装的 `fetch_episode.py`、`auralwise.py` 以及需要的渲染逻辑。不得调用脚本的长时间 `run` 模式。ASR 生命周期必须拆成并持久化：提交、外部 ASR 任务 ID、状态轮询和结果获取，以便恢复。
- 对经验证的免费单集，优先把已解析的 `audio_url` 传给 ASR 服务端拉取。不得把原始音频作为持久化资料、媒体文件或备份归档保存。
- 若服务端拉取明确失败，允许实现本地下载/上传兜底，但该文件仅可作为短期工作文件。任务到达成功、失败、拒绝或取消等任何终态时必须清理该临时音频及相关临时结果；清理失败必须记录为不含路径和敏感 URL 的运维事件。
- ASR 提交的成功响应必须持久化外部任务 ID，随后只能轮询和取回该 ID 的结果。提交请求超时、进程中断或响应不可确认时，任务必须标记为“提交结果不确定”或等效人工处理状态，绝不自动重新提交造成重复收费。
- 对已知的 ASR 结果，任务和播客记录必须保存实际可获得的状态、处理信息和计费金额/币种（若服务返回）。余额不足、无效凭据和服务端拒绝时必须返回可执行的说明；系统不得尝试自动充值，也不得要求用户在免费单集提交前确认费用。

### 5. 文字稿、全文 AI 分析和文章完成

- 成功获取的 ASR 结果必须生成可读的完整文字稿。文字稿应在保留可用说话人和时间信息的情况下写入 `Article.content`，不得只保存摘要、前 3,000 字或文件路径。`Article` 必须使用原小宇宙单集 URL、平台 `xiaoyuzhou` 和可用的标题、作者、发布时间等元数据。
- 播客生成的 Article 必须照常出现在现有文章列表、平台筛选、全文搜索、统计、DRF 序列化和 Django Admin 中。任务成功后必须关联该 Article，并在任务状态响应中返回可用的文章标识或安全的文章访问链接。
- 播客 AI 分析必须覆盖**全部**文字稿，不能复用会截断到 3,000 字的单次通用文章分析路径。系统必须按语义边界拆分为合理大小的块，优先利用 ASR 的段落、说话人或时间戳信息；每块的输入范围、状态和结果必须持久化。
- 每一块的 AI 分析必须可恢复和幂等。已成功的块在 worker 重启、租约恢复或重试后不得再次请求 AI 服务；失败的块必须阻止最终汇总并显示块级进度/错误。仅在全部块成功时，才允许进行一次最终汇总，并将汇总后的 `ai_summary` 和 `ai_key_point` 写入 Article。
- 若 AI 服务未配置、不可用或任一块/最终汇总失败，任务不得虚报“全文已分析”。系统必须保留已经取得的文字稿和明确的可恢复失败状态，提供用户可理解的重试路径；不得将未完成分析的文章标记为完整成功。

### 6. API、界面和管理体验

- 扩展任务 API，使客户端可轮询单一播客任务并获得：任务 ID、总体状态、当前阶段、总进度、分块分析进度、经脱敏的事件历史、可显示的错误/下一步、重试资格、取消资格、关联 Article 信息及已知成本/外部状态。现有任务列表 API 的读取行为必须继续可用。
- 提供明确的手动重试和取消 API。重试仅对可重试或需人工确认的非成功任务有效，且不得重置或重新提交已有外部 ASR 任务 ID。取消必须阻止尚未开始的后续阶段；已提交的 ASR 不能安全远程取消时，界面和事件必须明确说明本地处理已停止但可能已产生外部费用。
- 收藏页面必须以轮询方式更新播客处理卡片，使用合理的间隔并在浏览器页面卸载、终态或网络错误时停止/收敛轮询。卡片必须展示状态、阶段、总体进度、分析块进度、可显示事件、已知成本和可执行失败说明；失败时提供重试和取消操作，取消时提供正确状态反馈。
- 播客成功后，界面必须将其展示为普通内容或提供通往其文章内容的链接。接口和 UI 不得暴露 API key、音频 URL、外部任务敏感响应、临时文件路径或原始音频。
- Django Admin 必须可查看播客单集元数据、关联文章、任务阶段/状态/重试信息、已知成本和任务事件，以支持运营排障；敏感字段必须脱敏或不展示。

### 7. 数据迁移、兼容性和验证

- 数据库变更必须通过 Django migration 交付，并能在当前 SQLite 数据库上执行。既有 Article、CollectionTask、周刊、订阅和普通文章收藏数据不得被删除、重写或失效。
- 不新增用户未要求的运行时依赖、队列服务、Celery、Redis、密钥文件或持久音频存储。ASR 和 AI 凭据只可从现有安全环境配置机制读取，且绝不写入代码、迁移、测试夹具、文档示例或日志。
- 必须增加聚焦自动化测试，网络、子进程、ASR 和 AI 调用均须 mock。至少覆盖小宇宙 URL 验证与 202 异步提交、普通 URL 的兼容行为、活跃任务去重、免费/付费/私有判定、worker 阶段推进与租约恢复/并发安全、ASR 提交不确定时不重提、临时音频终态清理、取消/重试约束，以及长文字稿所有块均被处理和成功后才汇总。

## Non-Functional Requirements

- **响应时间与隔离：** 播客提交接口只执行验证和数据库持久化，应在不依赖外部元数据、音频、ASR 或 AI 完成的情况下响应。耗时操作只能在独立 worker 中执行。
- **可靠性：** 任务阶段、外部 ASR ID、块完成状态、事件和关联记录必须在每个可恢复边界持久化。任何重启后都必须可从数据库判断下一步，且不得重复 ASR/AI 计费调用。
- **安全与隐私：** 不记录或返回任何 secret、授权头、签名音频 URL、完整 ASR 请求/响应或持久原始音频。日志和事件只保留排障所需的脱敏错误分类与安全摘要。
- **可运维性：** worker 的运行方式、环境变量名称（不含值）、日志位置/查看方法、单 worker SQLite 限制和故障恢复步骤必须有文档。不得在实现过程中执行生产部署或重启生产服务。
- **兼容性：** 保持 Django 5.2、DRF、SQLite、Gunicorn、systemd 和现有 Bootstrap/原生 JavaScript 技术栈。不得要求 Celery、Redis、SSE 或 WebSocket。

## Acceptance Criteria

1. `POST /api/articles/collect/` 提交合法的小宇宙单集 URL 时，在 mock 的元数据/ASR/AI 服务均未调用的情况下，持久化一条播客任务并返回 HTTP 202，响应包含非空 task ID、状态查询 URL、阶段和进度。
2. 同一接口提交现有支持的非小宇宙 URL 时，仍走现有同步收藏流程并保持其当前成功、失败和重复文章语义；现有 API 测试通过。
3. 对不满足主机与 `/episode/<id>` 规则的小宇宙相关 URL，系统不会创建播客 ASR 任务；对非小宇宙 URL，不会错误标记为 `xiaoyuzhou`。
4. 同一单集 URL 在一个可处理任务存在期间重复提交时，系统不创建第二个外部 ASR 可提交任务，并返回或引用原任务；已存在的成功 Article 仍按现有重复收藏规则处理。
5. Worker 从持久化任务取得模拟的 `FREE`、非私有元数据后，按阶段保存元数据、ASR 外部任务 ID、轮询状态、文字稿和事件；任务成功时创建一个 `platform='xiaoyuzhou'` 的 Article，`content` 含完整可读文字稿，且该文章可被既有标题/内容/作者搜索和平台筛选返回。
6. 当模拟元数据的 `pay_type` 不是 `FREE` 或 `is_private` 为真时，任务结束为拒绝/不可重试状态，事件与 API 返回可执行原因，且断言 ASR 提交、下载和 AI 调用次数均为零。
7. 当元数据或音频访问发生可重试瞬时错误时，任务记录脱敏错误事件、按退避安排重试且不阻塞其他 Web 请求；当发生确定性失败时，不会无限重试，并返回相应可操作说明。
8. 单 worker SQLite 测试证明有效租约只能被一个 worker 领取；模拟 worker 崩溃或过期心跳后，另一 worker 可安全恢复未完成阶段，而已完成的 ASR 提交和 AI 块不会再次调用外部服务。
9. ASR 集成以绝对路径运行模拟的 Python 子进程，并分别测试 `submit`、`status` 和 `result` 生命周期。提交成功后持久化外部任务 ID；提交超时或响应不确定时，任务不自动再次提交，且重试 API 不会产生新的 ASR 提交。
10. ASR 结果包含计费数据时，任务 API/UI 可显示已知金额和状态。余额不足、无效凭据、限流和外部失败返回不含秘密或签名 URL 的行动建议，且没有任何自动充值调用。
11. 如果启用本地音频回退，测试证明临时文件只在工作期间存在，并在成功、失败、拒绝和取消的每一种终态均被删除；系统中没有持久原始音频字段或归档文件。
12. 给定超过 3,000 字且带模拟说话人/时间戳段落的文字稿，测试证明分块覆盖全部输入；每块成功结果都被持久化且只处理一次，只有所有块成功后才调用最终汇总并填充 `ai_summary` 和 `ai_key_point`。
13. 给定任一 AI 块或最终汇总失败，测试证明任务不报告全文分析成功、不写入伪完整摘要/核心观点、保留文字稿和块级进度，并可通过允许的重试恢复。
14. 收藏页面对模拟 202 响应展示播客处理卡片并轮询任务 API；卡片显示阶段、总体进度、分析块进度、脱敏事件/错误和已知成本，终态时停止轮询。成功时显示普通文章或链接，失败时仅在 API 允许时提供重试/取消操作。
15. Django migrations 在空测试库和现有迁移链上均可应用，`manage.py check` 通过，新增的聚焦测试在网络、ASR、AI 和子进程全部 mock 的条件下通过。
16. systemd worker unit 与运维文档随代码提交，内容说明单 worker SQLite 运行、环境配置、启动/停止/日志与恢复方式；实施过程不启动、停止、重启或部署任何实际 systemd 服务。

## Out of Scope

- 下载或转写真实播客、调用真实 ASR/AI 服务、读取/展示 API key、查询余额、自动充值或产生未经测试环境明确授权的外部费用。
- 收藏非小宇宙平台的音频/视频、节目主页、短链、RSS feed、付费内容、会员内容或私有内容。
- 原始音频、字幕、ASR JSON 或文字稿文件的长期媒体库、下载中心、备份或用户文件管理功能。
- Celery、Redis、消息队列、SSE、WebSocket、多 worker 分布式调度、数据库替换或与本功能无关的架构重构。
- 人工校对/命名说话人、自动推断真实身份、转写质量编辑器、热词人工审核界面和批量播客导入。
- 对已有普通文章 AI 分析策略、周刊、订阅、认证、邮件、前端整体样式或生产服务配置的无关修改。

## Change Record — 2026-11-17（设计评审 Finding 2 处理决定）

- 经需求方确认：**播客提交仅限已登录用户**。对有效小宇宙单集 URL 的 `POST /api/articles/collect/` 与批量收藏中的播客项，匿名调用返回 401 且不创建任务；普通文章 URL 的匿名收藏行为保持不变。
- 验收标准相应调整：原「该 POST 返回 202」适用于已登录用户；新增验收项——匿名播客提交返回 401，不产生任何持久化记录。
- 选择理由：播客提交会触发付费 ASR 外部调用，匿名提交存在被滥用产生费用的风险。
